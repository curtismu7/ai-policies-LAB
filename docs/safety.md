# Safety

- Loopback bind only (`AIPLAB_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it). The container runs as a non-root user, read-only, with every capability dropped.
- Host header must be a loopback name; writes must be same-origin.
- Netguard blocks every outbound connection (fetch, socket, DNS, UDP) with a self-test, and a test asserts zero attempts in the server process across the whole API in both modes. There is no worker thread and no child process. Notifications to Slack, a Ping push, Jira and ServiceNow are rows in an in-memory outbox (`delivered: false`); the "upstream tool" and the "issuer" are descriptions on `.example` hosts. Nothing is sent.
- **Real tokens, throwaway key.** A token minted here is a real RS256 JWT signed with an RSA key generated in memory when the process starts. The private half is never shown, logged or written; only the public half is published (`GET /api/jwks`). The token is labelled mock-issued and is not a credential for anything. Verification is strict: three base64url parts, header exactly `RS256` with the lab's key id (alg `none` and an HS256 key-confusion token are refused), the signature, issuer, audience, not-before and expiry against the lab clock, and a payload with no `__proto__`, `constructor` or `prototype` key.
- **The one response field the mask lets through is `labToken`** (the mint answer). A token the visitor presents is never echoed: the evaluation answer carries only the decoded header and claims of a token that verified, and the hop pane shows `[masked:keyed-value]`. A claim value that looks like a credential is refused at mint time.
- **Credential-shaped values the visitor types are masked, and the lab says it is a heuristic.** Free text (an approver comment, a simulated reply, claim values, argument values shown in a summary) is cleaned on the way in: zero-width, soft-hyphen and bidi characters are deleted, other control characters become spaces, credential-shaped runs are masked, and only then is the text cut to length. The detectors are lab-written and linear. Not every secret has a recognisable shape, so the page says not to type a real one. Every JSON answer is masked again as defence in depth. The canonical form of the arguments is shown as it is hashed unless it hides a credential-shaped value, in which case the masked copy is shown (the hash is always over the real arguments, which are never stored: an approval keeps only the hash and a masked summary). Error messages are fixed text and never include input; a route, tool, identity or person the lab does not know is never echoed; the final 404 and error handlers answer fixed JSON for every method and path; a workspace id that looks like a credential is refused.
- **The canonical form of a call is hostile-input tested** (`canon.js`): duplicate keys (also after NFC), `__proto__`/`constructor`/`prototype` keys, lone surrogates, raw control characters, numbers a double cannot hold exactly, nesting, size and count limits, text that is not JSON. A call that breaks a rule is a denial, never repaired or truncated.
- Every value used as an object key (vertical, scenario, layer, claim, argument) is checked with `Object.hasOwn` and a type test.
- Input is bounded: bodies 32 KB, arguments 4096 characters, a token 4096, a policy layer 30 rules, 200 approvals, 500 audit entries, 300 outbox entries, 40 hops per answer; a full workspace refuses new work with a clear code (Reset) instead of dropping anything. Workspaces are capped in count (500) and idle age (1 hour): **at the cap a new id is refused with 503 `workspaces_full` and nothing is ever evicted**, so flooding the lab cannot wipe another visitor's state (a test creates ids in parallel). The engine is synchronous, so check-and-add is atomic: parallel identical calls open one request, parallel approvals count once, a single-use grant is spent once (a test runs them in parallel).
- **Honest status codes.** An evaluation answers 200 (allow), 401 (a token that does not verify) or 403 (deny, hold, withheld result) and says which in the body (`result.outcome`). A refused write (self-approval, a bad role, a rule refused on save) is its own 4xx (403, 404, 409, 422). The browser logs every 4xx as a console message: that is expected in this lab, not a bug.
- The server writes no file (a test greps for write calls). The one home-directory touch is reading the optional shared settings file with `util.parseEnv`, taking only `AIP_LAB_MODE`.
- Only `.example` and `.invalid` hosts appear in any shipped text. The people, agents and applications are synthetic.
- Every product claim is labelled "Ping release claim, UNVERIFIED on our tenant" in the banner of every tab, in presenter mode too.
- **One normaliser, everywhere** (`credentials.js` `normalizeForMatching`): the cleaning of what the visitor types, the response mask, the canonical-form display, the inspection findings and the refusal of credential-shaped ids, claim values and rule values all match against the same normalised text (percent-decoded up to three rounds, NFKC, every Default_Ignorable, Cf and U+FFFD character deleted, control characters turned into spaces, backslashes before quotes dropped). A value shown beside a key that is a credential word is masked whole, in hop panes and token summaries too, and a claim or rule claim NAMED like a credential word is refused. An approval request keeps argument names and the call hash, never values. `masking-bypass.test.js` interleaves 25 invisible characters through four credential shapes and types each into every field of every endpoint, then does the same percent-encoded once and twice and with key-aware shapes, and searches every answer, the state and stdout/stderr in their normalised form.
